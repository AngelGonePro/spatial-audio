Why the old version lost background instruments: The side-channel encoding approach used (L−R)/2 to carry spatial data — but instruments panned near centre have nearly equal L/R energy, so they cancel out in the side signal and disappear. This version uses a full additive fold — every channel is summed with equal-power coefficients so nothing is ever subtracted or cancelled.

Highpasses SL/SR/BL/BR before folding so only LFE carries deep bass — fixes phase-smeared/uncomfortable bass on real discrete surround mixes (movies, native Atmos), where rear channels are independently mixed and can be out of phase with the front. Set to Off for content where the surrounds are synthetically upmixed from stereo (e.g. Atmos Music from a stereo source) — there, the surround bass is just a phase-correlated copy of the front bass already, so highpassing it only removes energy and dulls the low end instead of fixing anything.
Which setting for which source? Real 7.1/Atmos movie or music mixes with independently-authored surround channels → leave crossover at 100 Hz (default). Stereo-derived/upmixed-to-7.1 sources (like your Atmos Music workflow: stereo → synthetic 7.1 → downmix) → set crossover to Off.

Smooth Compressor (Pre-Limiter Stage)
〰️ RMS Soft-Knee Compressor Does the day-to-day gain work smoothly, before the hard limiter ever needs to
This is the "different kind of limiter" — genuinely different detection, not just gentler settings on the same mechanism. The Peak Limiter below reacts to instantaneous sample peaks (a hard, abrupt brickwall by design — that abruptness is exactly what caused the audible crackling on loud dialogue). This stage uses RMS detection (average energy over time, not instant peaks) with a soft knee (gain reduction ramps in gradually approaching the threshold, rather than doing nothing until it then clamping hard) — standard two-stage mastering practice. With this on, the hard limiter below should rarely need to do more than catch the rare genuine outlier, instead of doing all the work itself on every loud passage.

Peak / True-Peak Limiter
🔒 True-Peak Hard Limiter Pre-LUFS · Post-LUFS · Fade-Out Protection
Runs before and after loudnorm. Pre-limiter stops existing overs skewing LUFS analysis. Post-limiter hard-clamps anything loudnorm's gain boost pushes over ceiling — including fade-outs that loudnorm incorrectly raises. Attack default raised to 25ms: a 20-40Hz bass cycle is 25-50ms long, so a faster attack forces the limiter to change gain mid-cycle, which is heard as distortion on the bass itself, not just "loudness." 25ms gives it room to react smoothly across a full cycle without ever letting a sample exceed the ceiling.

CELT-only (via lowdelay — disables adaptive SILK/Hybrid mode-switching)
ffmpeg's libopus wrapper has no literal "force CELT" flag — this uses -application lowdelay, which explicitly disables the voice-optimized (SILK/Hybrid) modes, the closest available equivalent. Opus normally switches adaptively between SILK/CELT/Hybrid per-frame based on content, and that switching can occasionally produce subtle, content-dependent artifacts on some material. Forcing CELT-only removes the switching entirely, at a small honest cost: Hybrid mode's dialogue-specific efficiency (using SILK for the speech band) is unavailable, so dialogue-heavy passages may compress very slightly less efficiently. At 320kbps+ this tradeoff is negligible. Untoggle to restore full adaptive mode if you're not seeing the artifact this was meant to fix.
